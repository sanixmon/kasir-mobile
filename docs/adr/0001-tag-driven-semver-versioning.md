# 1. Tag-Driven SemVer Release and Monotonic Git Version Code

The mobile app previously created a GitHub Release on every push to master while leaving the Android `versionCode` statically hardcoded at 6, leading to upgrade installation failures on user devices and release noise. We decided to decouple continuous integration from release distribution: CI runs tests and build checks on pull requests and master commits, while production releases are triggered exclusively by annotated Git tags (`v*`) or manual workflow dispatch. `versionName` follows semantic versioning (`MAJOR.MINOR.PATCH`) with Gradle property overrides, and `versionCode` is computed automatically from the Git commit count (`git rev-list --count HEAD`) to guarantee strictly monotonically increasing build numbers across local and CI builds.
